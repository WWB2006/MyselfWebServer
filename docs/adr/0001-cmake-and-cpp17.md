# ADR 0001：使用 CMake 与 C++17

- 状态：已采纳
- 日期：2026-09-24
- 相关阶段：阶段 0

## 背景

项目需要在 Ubuntu 上长期开发，后续还要接入单元测试、持续集成与性能测试；
同时希望同一份代码在 Windows 上也能构建，便于跨平台验证与打包。
语言标准需要一个稳定、库支持充分、招聘市场普遍使用的版本。

## 选项

1. **手写 Makefile**：依赖最少、启动最快，但手工维护依赖关系，跨平台与接入测试框架的成本高。
2. **CMake**：跨平台、生态成熟，GoogleTest 与 Qt 都能直接接入，社区资料充足。
3. **Bazel 或 Meson**：功能强，但对单人学习项目偏重，环境搭建成本高于收益。

## 决定

- 使用 **CMake 3.16 及以上版本**，采用现代 CMake 写法（target 语义而不是全局变量）；
- 语言标准固定为 **C++17**，不引入 C++20 特性，避免不同编译器支持差异带来的麻烦；
- 核心代码编译为静态库 `myself_core`，可执行文件与单元测试分别链接它；
- 通过 `file(GLOB_RECURSE ... CONFIGURE_DEPENDS)` 收集源文件，新增文件无需改脚本；
- 单元测试通过选项 `-DWEBSERVER_BUILD_TESTS=ON` 控制，默认关闭以保证离线可构建。

## 代价

- 需要理解现代 CMake 的 target 与作用域规则，初次上手比手写 Makefile 慢；
- `GLOB` 的写法在大型项目中通常不被推荐（构建系统无法精确追踪依赖），
  本项目用 `CONFIGURE_DEPENDS` 缓解，文件规模变大后可以改为显式列出源文件；
- 静态库拆分带来一次额外的链接配置，但换来了测试与业务代码解耦。

## 后续观察

- 如果后续引入第三方日志库或 JSON 库，优先用 FetchContent 并验证离线构建路径；
- 当源文件超过约 50 个时，评估把 `GLOB` 换成显式源文件列表；
- 如果要在 Windows 上稳定构建，需要固定 MSVC 或 MinGW 工具链版本，避免混用。
