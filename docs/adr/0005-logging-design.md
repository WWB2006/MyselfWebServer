# ADR 0005：日志系统的前后端分离与异步落盘

- 状态：已采纳
- 日期：2026-09-26
- 相关阶段：阶段 6

## 背景

阶段 5 之前所有输出都是 `std::cout` / `std::cerr`，问题有三个：

1. 没有级别，压测时想关掉详细输出只能改代码；
2. 多线程下输出内容交错，看不出是哪条连接、哪个线程打的；
3. 直接写标准输出或磁盘会阻塞业务线程，压测时直接影响 QPS。

## 选项

1. **继续用 iostream，只加一个级别判断**：改动最小，但每条日志仍会触发字符拼接与锁竞争；
2. **引入成熟日志库（spdlog / glog）**：功能完善，但本项目的目的之一是理解日志系统内部结构，
   而且第三方库会掩盖"为什么会阻塞"这个问题；
3. **自研，前端/后端分离**：前端只做格式化（栈上缓冲），后端决定写到哪里（控制台或异步文件）。

## 决定

采用方案 3，结构如下：

| 组件 | 职责 |
| --- | --- |
| `LogStream` + `FixedBuffer` | 栈上固定缓冲，零分配地拼接整数、浮点、字符串、指针 |
| `Logger` | 级别过滤、时间戳、线程 id、`文件:行号`，输出函数可替换 |
| `LogFile` | 追加写文件，按大小（默认 32MB）与日期轮转 |
| `AsyncLogging` | 后台线程 + 双缓冲，前端只追加到缓冲，后端批量落盘 |

具体约定：

- 宏 `LOG_INFO << ...` 先做级别判断（`if (Logger::level() <= kInfo)`），
  低于阈值的日志连字符串拼接都不会发生；
- 时间戳使用 `CLOCK_REALTIME`（日志要能和人看到的时间对上），
  而定时器使用 `steady_clock`（阶段 5 的决定），两者刻意分开；
- 后台线程用**双缓冲**：前端写满一块就交给后端，后端批量写文件，避免每条日志一次 write；
- 输出目标通过函数指针注入，`main` 里把它设为"异步文件 + 可选控制台"；
- 控制台输出可用 `-q` 关闭，压测时避免终端拖慢程序；
- `LOG_FATAL` 打完日志后 `abort()`，用于不可恢复错误。

## 代价

- 自研意味着功能有限：没有日志采样、没有结构化字段、没有多目标路由；
- 异步日志在进程被 `kill -9` 时会丢掉缓冲里的最后一批日志（最多 4MB 或 3 秒），
  这是异步方案的固有代价，需要立即落盘的场景应使用同步模式；
- 前端缓冲固定 4KB，超长单条日志会被截断，需要在代码里避免一次打印超大字符串；
- 级别判断写在宏里，非 `if` 语境（例如 `if (x) LOG_INFO << ...; else ...`）会踩悬空 else 的坑，
  这是 muduo 风格宏的已知问题。

## 后续观察

- 阶段 7 的指标接口需要统计日志行数，可在此基础上加计数器；
- 压测时对比 `-l warn`、`-l info`、`-q` 三种配置的 QPS，把数据写进验收记录；
- 如果后续需要结构化日志（JSON）或采样，评估切换到 spdlog 的代价。
