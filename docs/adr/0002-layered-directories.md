# ADR 0002：目录分层与依赖方向

- 状态：已采纳
- 日期：2026-09-24
- 相关阶段：阶段 0

## 背景

网络服务器的代码天然容易耦合：事件循环、协议解析、业务处理与日志往往混在几个文件里，
结果是改一处要重新验证全部功能，测试也无法单独进行。
在阶段 0 定下目录与依赖规则，成本最低；等到阶段 3 之后再拆，代价会高很多。

## 选项

1. **单目录平铺**：所有 `.cpp` 放一起，简单直接，但十几个文件后就难以定位；
2. **按层切分**（net / http / timer / thread / log / util）：层次清晰，依赖关系可以显式约束；
3. **按功能切分**（连接管理 / 设备会话 / 数据输出）：贴近业务，但本项目业务简单，会过度设计。

## 决定

采用按层切分，并规定**依赖只能单向流动**：

| 模块 | 职责 | 允许依赖 |
| --- | --- | --- |
| `util` | 配置、时间戳、版本、通用工具 | 无 |
| `log` | 日志接口与异步落盘 | util |
| `net` | Socket、事件循环、连接管理、缓冲区 | util、log |
| `http` | 请求解析、响应构造、路由 | net（只通过回调与 Buffer 交互） |
| `timer` | 定时任务与超时管理 | util、log |
| `thread` | 线程池与事件循环线程 | util、log |
| `main.cpp` | 装配：读配置、创建对象、启动循环 | 以上全部 |

另外两条具体约定：

1. **协议层不依赖网络层**：`http` 的解析器只接收字节数组（Buffer），不持有 socket，
   因此可以脱离网络做单元测试；
2. **头文件与实现分离**：对外头文件放 `include/myself/`，实现放 `src/`，相对路径保持一致。

## 代价

- 初期文件数量比单目录方案多，需要投入时间维护目录约定；
- 跨模块调用需要先设计接口，写代码前多想一步；
- 如果出现循环依赖，说明分层划分错了，必须先抽出接口而不是绕过规则。

## 后续观察

- 阶段 3 引入 HTTP 后，检查是否出现 `http` 反向依赖 `net` 内部实现的情况；
- 阶段 4 引入线程池后，确认线程模块不反向依赖 `net` 的连接对象；
- 阶段 9 抽库时，评估把 `net`、`timer`、`thread` 抽成可独立复用的组件。
