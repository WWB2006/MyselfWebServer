## 二、功能验收

| 序号 | 检查项 | 命令 | 期望结果 | 实际结果 |
| --- | --- | --- | --- | --- |
| 1 | 构建与启动 | `cmake --build build -j$(nproc) && ./build/webserver -p 8080 -r www` | 正常启动并监听 |  |
| 2 | 首页 | `curl -i http://127.0.0.1:8080/index.html` | `200 OK`，带 `Content-Length` 与 `Content-Type: text/html` |  |
| 3 | 根路径映射 | `curl -i http://127.0.0.1:8080/` | `200 OK`，返回与 `/index.html` 相同内容 |  |
| 4 | 未命中返回 404 | `curl -i http://127.0.0.1:8080/not-exist` | `404 Not Found`，且连接正常关闭而不是被直接断开 |  |
| 5 | 浏览器可访问 | 浏览器打开 `http://<主机IP>:8080/` | 页面正常渲染，不一直转圈 |  |
| 6 | 目录穿越防护 | `curl -i --path-as-is http://127.0.0.1:8080/../etc/passwd` | `400` 或 `404`，**不得**返回 `/etc/passwd` 内容 |  |
| 7 | 请求头不完整时等待 | 用脚本只发送 `GET / HTTP/1.1\r\n` 后暂停 | 服务端等待剩余头部，不误判为完整请求 |  |
| 8 | 半包请求 | 用脚本把一条完整请求拆成两次发送 | 解析器拼齐后才响应，返回正确结果 |  |
| 9 | 粘包请求 | 一次发送两条完整请求（pipelining） | 依次返回两个响应，顺序正确 |  |
| 10 | 超长请求头 | 发送一行 64KB 的请求头 | 返回 `400` 或 `413`，不崩溃、不无限增长内存 |  |
| 11 | 无 fd 泄漏 | 上述用例全部跑完后 `ss -tn state established \| wc -l` | 回到接近 0 |  |

## 三、交付物核对

| 交付物 | 完成标准 | 状态 |

| `HttpParser` | 有限状态机覆盖请求行、请求头、请求体、完成四个状态 | □ |

## 四、结论与遗留问题

结论：

| 问题 | 影响 | 计划 |
| --- | --- | --- |
| 单线程串行处理请求 | 并发能力受限于单核 | 阶段 4 引入线程池与主从 Reactor |
| 大文件读取在 IO 线程内完成 | 阻塞事件循环 | 阶段 4 交给 worker 线程池处理 |
