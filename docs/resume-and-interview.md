# 简历条目与面试准备

## 一、简历条目（开发版）

> 每条要点都必须有证据；没有证据的表述请删掉或降级。

1. 使用 C++17、epoll ET 与主从 Reactor 实现跨平台 HTTP 服务器（约 6000 行，独立完成核心模块），
   主线程只负责 accept，多个 IO 线程按 one loop per thread 分担读写。
   证据：`include/myself/net/`、ADR 0003。
2. 自研 HTTP/1.1 解析状态机，处理半包、粘包与 pipelining，实现静态文件服务与路由注册，
   并对目录穿越与超长请求做防护。证据：`src/http/HttpParser.cpp`、单元测试 14 个用例。
3. 实现由 epoll_wait 超时驱动的定时器，支持一次性/重复任务与取消，用于空闲连接超时与周期统计；
   实现分级异步日志（双缓冲落盘、按 32MB 轮转）。证据：ADR 0004、ADR 0005、`logs/` 样例。
4. 接入 Prometheus 指标与过载保护：暴露 12 档延迟直方图与连接/请求/拒绝计数，
   连接数超过上限时立即返回 503；并用压测矩阵与火焰图定位瓶颈。
   证据：`/metrics` 输出、`docs/bench/` 数据、ADR 0006、ADR 0008。
5. 实现 L7 自适应令牌桶限流（惰性补发、突发容量、`429` + `Retry-After`、运维接口白名单），
   并修复短连接下提前 `shutdown(SHUT_WR)` 触发 `EPIPE` 与 TCP RST 的时序缺陷（改为输出缓冲
   drain 后延迟半关闭）；压测中精准拦截 16032 次超额请求且零崩溃。
   证据：`include/myself/util/TokenBucket.h`、`docs/stage-10-令牌桶限流与过载保护.md`。
6. 实现 HTTP 条件请求（RFC 9110 §13）：用一次 `stat(2)` 生成强 `ETag` 与 `Last-Modified`，
   支持 `If-None-Match`（强/弱/列表/`*`）与 `If-Modified-Since`，命中返回零 Body 的
   `304 Not Modified`，并暴露 `myself_requests_not_modified_total` 统计省下的整包传输。
   证据：`src/http/Router.cpp`、`docs/stage-11-ETag与条件请求.md`。
7. 实现静态文件 `sendfile(2)` 零拷贝传输：按 64KB 阈值分流，大文件由内核在 PageCache 与
   socket 缓冲之间直接对拷，用户态零参与；用 `preFileBytes_` 三阶段写路径保证 pipelining
   下的响应顺序，并处理 ET 模式 EAGAIN 续传、文件截断、连接中断释放 fd 等边界。
   证据：`include/myself/util/FileBody.h`、`docs/stage-12-零拷贝文件传输.md`、
   `scripts/bench_zero_copy.sh`。

## 三、三分钟项目讲解稿

**30 秒（问题与定位）**
这是一个基于 epoll ET 与主从 Reactor 的 C++17 HTTP 服务器，目标是解决"高并发下连接管理与
可观测性"的问题。它支持静态文件与状态接口、分级异步日志、Prometheus 指标、过载保护与优雅退出。

**60 秒（架构与关键模块）**
主线程只跑一个事件循环负责 accept，accept 后轮询把连接分配给若干 IO 线程，每条连接绑定到固定
线程，避免跨线程操作 epoll。连接用 shared_ptr 管理、Channel 持有 weak_ptr 保活，读写走
Buffer；解析层是请求行/头/体三段状态机，只吃字节数组不碰 socket，所以能单独做单元测试；
定时器把最近到期时间交给 epoll_wait 当超时值；日志前后端分离，前端零分配格式化，后端后台线程
双缓冲落盘。

**60 秒（我独立完成的部分与难点）**
事件循环的跨线程投递是我自己实现的：用 eventfd 唤醒阻塞中的 epoll_wait，并加了线程归属断言，
把过去那种"偶发崩溃"变成立刻暴露的错误。难点在处理半包与写回：半包靠状态机保留中间状态，
写不完的数据必须进输出缓冲并注册 EPOLLOUT，否则会静默丢数据。第二个难点是退出顺序：
必须先把连接交回各自的 IO 线程关闭，再回收线程池，否则会在错误线程析构连接。

**30 秒（数据与结果）**
在四核虚拟机上，用 wrk 做并发梯度压测得到 QPS 与 P99 曲线；火焰图显示热点集中在日志输出与
缓冲区拷贝，把日志级别调到 warn 并启用异步落盘后 P99 明显下降；故障注入六个场景全部通过，
长稳测试中 RSS 增长在 5% 以内。

## 四、高频追问与回答要点

| 追问 | 回答要点 |
| --- | --- |
| 为什么用 ET 不用 LT | ET 减少重复通知与系统调用，但要求循环读到 EAGAIN；LT 实现更简单但事件触发频繁。选 ET 是为了高效，代价是必须严格处理非阻塞与循环读 |
| ET 模式下最容易犯的错 | 忘了循环读到 EAGAIN，导致剩余数据要等下一次事件；以及 accept 只调一次，导致积压连接无人处理 |
| 连接为什么绑定固定线程 | 连接状态（缓冲区、定时器、Channel）不加锁，只有在固定线程访问才安全；跨线程只投递任务 |
| runInLoop 怎么实现 | eventfd 注册进 epoll，跨线程投递时写 8 字节唤醒；任务在循环线程的待办队列里执行 |
| 定时器为什么不用 timerfd | 把最近到期时间作为 epoll_wait 超时值更轻量，且任务天然在循环线程执行；代价是精度受循环影响 |
| 半包与粘包怎么处理 | 有限状态机记录解析进度；半包返回等待，粘包在循环里继续解析同一缓冲区 |
| 写一半怎么办 | 剩余数据进输出缓冲并注册 EPOLLOUT，可写事件里继续发送，发完取消关注 |
| SQL/数据库用过吗 | 本项目无数据库；如果被问，说明你在项目三里用过 SQLite（阶段三项目） |
| 日志如何避免影响性能 | 级别过滤在宏里先判断，前端零分配，后台双缓冲异步落盘，压测时用 `-q` 关闭控制台输出 |
| 指标怎么统计 | 原子计数器 + 12 档直方图，Prometheus 的 `le` 桶按累计语义输出，精确分位用 `histogram_quantile` |
| 过载保护怎么做 | 超过 `-m` 上限立即返回 503 并计数，避免连接堆积成雪崩；更完整的方案是排队与背压 |
| 优雅退出怎么保证不丢数据 | 信号只设标志，循环里检测后先停接收、再关闭连接、停线程池、刷日志、停异步日志线程 |
| 怎么定位内存问题 | ASan 与 Valgrind 跑单元测试与小规模请求；长稳测试看 RSS 曲线；TSan 查数据竞争 |
| 怎么定位性能瓶颈 | wrk 拿基线，perf 采样生成火焰图，一次只改一个变量再复测 |
| 为什么拆静态库 | 测试要链接业务代码；可执行文件只保留 main，测试与产物解耦 |
| 接口测试为什么用真实进程 | 覆盖 epoll、线程与关闭路径；代价是要处理端口与启动时序，用轮询等端口就绪 |
| 测试覆盖了哪些边界 | 半包/粘包/pipelining、超长请求头、非法 Content-Length、目录穿越、定时器取消与自取消、指标空操作 |
| CI 里为什么不跑性能测试 | runner 性能抖动大，数据不可比；性能测试放在固定机器上手工执行并归档 |
| 项目的最大不足是什么 | 没有做 HTTP/2 与 TLS；定时器精度受循环影响；过载保护是直接拒绝而非排队 |
| 如果让你重做会怎么改 | 解析层改为零拷贝（`string_view` + 分段缓冲）；定时器换时间轮以支持大量任务；把指标与日志换成成熟的库以降低维护成本 |
